    **Pre-flight on the dev machine (laptop):**
    1. `pytest tests/` — full suite green, no regressions.
    2. `( cd src/shitbox/dashboard/static/vendor && sha256sum -c SHA256SUMS )` — clean.
    3. `git diff --stat src/shitbox/events/sampler.py` — empty (sampler untouched, RESEARCH OQ1 honoured).

    4. `python -m tools.download_tiles --config config/config.yaml --out /tmp/test.mbtiles --zoom-min 5 --zoom-max 8`

    7. `sudo systemctl restart shitbox-telemetry` (or `python -m shitbox.events.engine` for foreground)

    9. From a phone on rally wifi: open `http://<pi-lan-ip>:8080` — page should load.
    10. From the Pi's Chromium kiosk: open `http://localhost:8080` — page should render the full layout.

    - [ ] IMU temp + SoC temp tiles show real numeric values (or `—` if sensor missing)

    - [ ] Live position dot appears once GPS has a fix
    - [ ] Bottom strip empty initially, populates when an event fires (slap the steering wheel or trigger the manual button)
    - [ ] Mobile phone view reflows to single column

    **Interaction checks:**

    - [ ] Wait 10 seconds without touching — map smooth-pans back to live position (D-20)

    - [ ] Open a 9th browser tab to /sse/fast — should get HTTP 503 (D-03)

    - [ ] `journalctl -u shitbox-telemetry -f` — confirm IMU sample rate stable, no dropped samples warnings, no GC pressure complaints
    - [ ] Trigger an event (manual button or aggressive driving) — confirm video saves successfully to /captures/, AND the event appears in the dashboard event strip within ~1 second

    - [ ] Bind another process to port 8080, restart daemon — daemon should log `dashboard_start_failed` and keep capturing
