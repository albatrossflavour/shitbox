## What the plan is actually about (plain terms)

Four monitoring gaps from v1.0:

1. **Undervoltage is broken in software.** The bug is at `src/shitbox/health/thermal_monitor.py:297` — it compares the whole `vcgencmd get_throttled` value, so sticky since-boot bits 16-19 swallow real transitions on bits 0-3. Fix: compare `raw & 0xf`, require the non-zero mask to hold for ~2-3 reads before firing. Add a recovery path when the mask clears.
2. **Capture failure is invisible.** ffmpeg stalls are detected in `ring_buffer._is_stalled()` but don't reach the dashboard. Wire them up: `CAPTURE_FAILURE` on first stall, `CAPTURE_RESTORED` on recovery, `CAPTURE_DOWN` after N=3 restart attempts in ~90s.
3. **MQTT scrape job needs deleting.** The `shitbox-mqtt-exporter` job is already commented out in `~/dev/home-ops/kubernetes/apps/observability/kustomization.yaml:20`; researcher confirmed zero Grafana references. Work: `rm -rf kubernetes/apps/observability/shitbox-mqtt-exporter/` + commit.
4. **HLTH-01 is already working.** Metrics are live in Grafana. This is ticket closure, not a code change.

Plus the Health page evolution (D-13, user add):
- Expand the existing dashboard hardware panel into a Health page with sticky colour state for system conditions — so a missed overlay doesn't mean a forgotten condition.
- Single modal section `SYSTEM` above the existing `HARDWARE` list.
- 60s RESTORED green fade → CLEAR grey idle.
- Green recovery overlay reuses the existing `alertOverlay` element with `_CLEARED`/`_RESTORED` subtype routing (3s vs 10s).
