<context>
The core insight from this session: the thermal and CPU load problem is the
camera output format, not the compute. MJPEG-only cameras require continuous
software encode. The fix is a camera that outputs H.264 natively (stream copy).
The Pi 5 having no hardware H.264 encoder makes this non-negotiable.

The BME680 issue was a red herring -- sensor was fine, I2C bus state was the
problem, power cycle fixed it. Retry loop is still worth keeping defensively.
