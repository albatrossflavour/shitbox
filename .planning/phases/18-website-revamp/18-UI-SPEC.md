## Spacing Scale

Declared values (multiples of 4). Units expressed in rem as-used in the existing site.

| Token | Value | CSS Equivalent | Usage |
|-------|-------|----------------|-------|
| xs | 4px | 0.25rem | Icon gaps, badge internal padding, note icon offset in card corner |
| sm | 8px | 0.5rem | Gap between nav items, inline element gaps |
| md | 16px | 1rem | Card padding (status-card), default element spacing |
| lg | 20px | 1.25rem | Note card horizontal padding only — see Exceptions |
| xl | 24px | 1.5rem | Main content padding, section bottom margin, about-card padding |
| 2xl | 32px | 2rem | Header horizontal padding, main horizontal padding |
| 3xl | 48px | 3rem | Empty/loading state vertical padding |

Exceptions:

- Map height: `70vh` (existing), Status mini-map height: `400px` (existing) — do not change
- Note icon badge in event card corner: `4px` offset from card edge, `20px` touch target — no
  layout change to the card
- Fuel popup content uses existing Leaflet popup sizing — no custom override needed
- `lg = 20px` (1.25rem): not a multiple of 4 and therefore not a standard token. Justified as the
  horizontal padding of `.note-card` (`padding: 1rem 1.25rem`) which matches the existing pattern
  for asymmetric card padding (more horizontal breathing room than vertical). This value is used
  only in `.note-card` horizontal padding. Do not generalise it to other components.

Source: measured from existing CSS, lines 94, 104, 340, 491-504.

## Typography

The site uses one font stack and a narrow range of sizes. Match exactly.

| Role | Size | Weight | Line Height | Colour |
|------|------|--------|-------------|--------|
| Body | 16px (1rem base) | 400 | 1.6 | `#c9d1d9` |
| Label / meta | 12-13px (0.75-0.8rem) | 400 | 1.5 | `#8b949e` |
| Sub-heading / section title | 14px (0.875rem) | 500 | 1.4 | `#e0a040` or `#c9d1d9` |
| Card heading / value | 16-22px (1-1.4rem) | 600 | 1.2 | `#f0dbb8` |

Notes:

- Four sizes only: 12px, 14px, 16px, 22px. Nothing outside this range.
- Two weights only: 400 (regular) and 600 (semibold). The existing `font-weight: 500` on nav
  items and sub-headings is an existing inconsistency — match it only where reusing those exact
  components.
- `text-transform: uppercase; letter-spacing: 0.05em` is used on `.status-label` — apply this
  same treatment to Drivers tab table header labels and note card meta labels.
- Note card body copy: 16px, weight 400, `#c9d1d9`, line-height 1.6. Full paragraph text, not
  truncated.
- Note card timestamp: 12px, weight 400, `#8b949e`.

Source: lines 37-53, 230-233, 496-503.

## Component Inventory

New components to implement, defined precisely enough for the executor to build without design
ambiguity. All components are vanilla HTML+CSS; no framework.

### 1. Note Card (Status tab notes feed)


### 5. Fuel Stop Map Pins

Fuel stops added as a separate `L.layerGroup()` after event markers in `initMap()`. Rendered
after the events loop so fuel pins appear on top. Pin geometry:

```js
L.circleMarker([stop.lat, stop.lng], {
    radius: 8,
    fillColor: '#c06000',
    color: '#fff',
    weight: 2,
    opacity: 0.9,
    fillOpacity: 0.85
})
```

Popup content (inline HTML string matching existing popup pattern):

```
Fuel Stop
[date] [time]
Volume: X.X L
This stop: X.X km/L
Running avg: X.X km/L
```

Popup structure:

```html
<div class="map-popup">
  <div class="popup-type" style="color:#c06000">Fuel Stop</div>
  <div class="popup-detail">
    {dateStr} {timeStr}<br>
    Volume: {volume_litres} L<br>
    This stop: {efficiency_kml} km/L<br>
    Running avg: {cumulative_avg_kml} km/L
  </div>
</div>
```

No cost data. No link. No additional controls. Cost field must never appear even if present in
the JSON object (access only the whitelisted fields above).

Fuel stops loaded via `fetch('/captures/fuel.json', { cache: 'no-cache' })` parallel to the
existing events fetch. If the fetch fails or returns empty, the map renders normally without
fuel pins (silent failure, no error message on the Map tab).

## Interaction Contracts

### Navigation

New "Drivers" tab follows the existing `nav a[data-section]` + `.section.active` pattern exactly.
The `validSections` array must have `'drivers'` added. Hash routing: `#drivers` navigates to the
tab. The existing nav click handler does not require modification beyond adding the new tab link
and section div.

Insert order in `<nav>`: Status | **Drivers** | Videos | Timelapse | Map | Dashboard | The Car |
Route | About.

### Data Loading

Three new fetches on page load, parallel to the existing events fetch:

1. `fetch('/captures/notes.json')` — populates notes feed in Status tab and note badges on
   event cards
2. `fetch('/captures/fuel.json')` — populates fuel stop layer in `initMap()` when Map tab
   is activated
3. `fetch('/captures/driver-stats.json')` — populates Current Driver card (Status tab) and
   Drivers tab table

All three use `{ cache: 'no-cache' }`. All three fail silently — if the file doesn't exist
(404) or is malformed, the relevant UI element shows its empty/unavailable state and the rest
of the page continues functioning normally.

Note badge injection: after `renderEvents()` populates the card DOM, the notes fetch result
is used to inject `.note-badge` into matching event cards. Match is by event ID. If
`driver-stats.json` fetch resolves before or after `renderEvents()`, the Current Driver value
is set whenever the data arrives (idempotent DOM update).

### Map Tab Activation

`initMap()` is currently called either on tab click (if `eventsData` is ready) or at the end
of the events fetch (if Map tab is already active). Fuel stops must be added inside `initMap()`
after the existing event markers loop. The fuel layer depends on the fuel fetch having resolved
-- store the fuel data in a module-level var (`var fuelData = null`) and check it inside
`initMap()`. If null, skip fuel layer silently.

### Status Tab

Notes feed is appended below `#status-map`. After `renderStatus()` populates the status cards
and map, a `renderNotes(notesData)` function appends the notes feed section. Notes are sorted
newest first. Maximum display: no limit (show all notes).

Current Driver card is added to the `.status-grid` alongside existing cards. It is populated
in `renderStatus()` if `driverStatsData` is available, otherwise shows `—`.
