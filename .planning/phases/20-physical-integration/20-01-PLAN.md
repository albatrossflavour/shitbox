<objective>
Design the Pi 5 stack enclosure in OpenSCAD, ready for PETG printing.

Purpose: House the full Pi 5 stack (NVMe HAT, Pi 5 board, active cooler, double-height GPIO
extension, Adafruit perma-proto) in a 3D-printed PETG case that mounts to the plywood
electronics panel in the car. The case must survive thousands of kilometres of corrugated
roads with positive airflow cooling, locking connectors for the sensor loom, and serviceable
cable management.

Output: `hardware/pi-case.scad` — parametric OpenSCAD source producing tray + lid geometry.
</objective>

  <action>
    Gather physical measurements of the Pi 5 stack using calipers. These measurements are the
    critical input for the SCAD design in Task 2. Without them, the enclosure dimensions will
    be wrong and the print will not fit.

    Measure the following to the nearest 0.5mm:

    **Stack height (critical path — determines case interior height):**
    1. Assemble the full stack: NVMe HAT on bottom, Pi 5 on HAT standoffs, active cooler clipped
       to SoC, double-height GPIO extension header on GPIO pins, perma-proto on top of extension
    2. Measure total height from NVMe HAT PCB bottom surface to perma-proto PCB top surface
    3. Measure NVMe HAT standoff height (gap between HAT PCB top and Pi 5 PCB bottom)
    4. Measure active cooler height above Pi 5 PCB top surface (heatsink + fan blower)
    5. Measure double-height GPIO extension height above Pi 5 GPIO pin tops

    **Connector positions (for cable exit placement):**
    6. Measure distance from Pi 5 board edge to centre of each HDMI micro port (there are two)
    7. Measure distance from Pi 5 board edge to centre of each USB port
    8. Measure USB-A port height above PCB (for exit slot sizing)
    9. Measure HDMI micro port height above PCB (for exit slot sizing)

    **Fan confirmation:**
    10. Confirm the intended fan: is it the 40x40x10mm Noctua NF-A4x10 (5V), or a different
        30mm fan? The NF-A4 series is 40mm — D-04 says "30mm" which is likely the cooler
        height, not the fan frame size.
  </action>

<task type="auto" tdd="false">
  <name>Task 2: Design Pi 5 stack enclosure in OpenSCAD</name>
  <files>hardware/pi-case.scad</files>
  <read_first>
    - hardware/sensor-cluster.scad (reference analog — reuse conventions exactly)
    - .planning/phases/20-physical-integration/20-PATTERNS.md (connector cutout patterns, naming conventions)
    - .planning/phases/20-physical-integration/20-RESEARCH.md (hardware dimensions reference, pitfalls)
  </read_first>
  <action>
    Create `hardware/pi-case.scad` following the sensor-cluster.scad conventions exactly.

    **File structure (in this order):**

    1. File header comment: project name, part description ("Pi 5 stack enclosure"),
       orientation note ("NVMe HAT on floor, HDMI/USB ports face [SIDE based on measurements]"),
       stack order, all measured dimensions with date and source, units: mm.

    2. `$fn = 64;`

    3. Parametric constants blocks (SCREAMING_SNAKE_CASE, grouped by concern):

       Print/material block — reuse from sensor-cluster.scad:
       ```
       OUTER_WALL = 2.0;
       FLOOR      = 2.0;
       PCB_TOL    = 0.6;
       ```

       Pi 5 board block:
       ```
       PI5_W      = 85.0;   // board width (verified RPi mechanical drawing)
       PI5_D      = 56.0;   // board depth
       PI5_HOLE_D = 2.9;    // mounting hole clearance (M2.5)
       PI5_INSET  = 3.5;    // hole inset from edge
       PI5_HOLE_W = 58.0;   // hole spacing width (49mm per drawing — VERIFY)
       PI5_HOLE_D_SPACING = 49.0; // hole spacing depth
       ```

       Stack block — use measurements from Task 1:
       ```
       STACK_H       = <measured>;  // full stack height
       HAT_STANDOFF  = <measured>;  // NVMe HAT to Pi gap
       COOLER_H      = <measured>;  // cooler above Pi PCB
       GPIO_EXT_H    = <measured>;  // extension header height
       ```

       Connector/port position block — from Task 1 measurements:
       ```
       HDMI1_OFFSET  = <measured>;
       HDMI2_OFFSET  = <measured>;
       USB1_OFFSET   = <measured>;
       USB2_OFFSET   = <measured>;
       USB_PORT_H    = <measured>;
       HDMI_PORT_H   = <measured>;
       ```

       Fan block (per D-04, default 40mm unless Task 1 says otherwise):
       ```
       FAN_W         = 40;
       FAN_MOUNT_SPG = 32;   // mounting hole spacing
       FAN_SCREW_D   = 3.4;  // M3 clearance
       FAN_APERTURE  = 37;   // airflow hole diameter
       ```

       Connector cutout block (per D-05, D-06):
       ```
       GX12_D        = 12.5; // 12mm + 0.5mm clearance
       SMA_HOLE_D    = 6.7;  // 6.35mm + 0.35mm clearance
       ```

       Mounting standoff block (per D-03 — rubber standoffs, NOT self-tap):
       ```
       STANDOFF_HOLE_D = 2.7;  // M2.5 clearance (through-hole, not self-tap)
       STANDOFF_BOSS_D = 6.0;  // boss OD
       STANDOFF_H      = 4.0;  // rubber standoff compressed height
       ```

       Mounting flange block — reuse from sensor-cluster.scad:
       ```
       FLANGE_W      = 12;
       FLANGE_THICK  = FLOOR;
       BOLT_D        = 4.5;
       BOLT_HEAD_D   = 8.5;
       ```

       Lid block:
       ```
       LID_THICK     = 1.6;
       LID_SCREW_D   = 2.7;
       LID_BOSS_D    = 6;
       LID_BOSS_HOLE = 2.1;
       ```

       Cable exit block (per discretion — individual sized slots with zip-tie tabs):
       ```
       HDMI_SLOT  = [14, 8];   // right-angle HDMI adapter body
       USB_SLOT   = [14, 7];   // USB-A cable
       PWR_SLOT   = [8, 5];    // barrel jack or USB-C power cable
       QWIIC_SLOT = [6, 4];    // Qwiic/STEMMA QT cable
       ONEWIRE_SLOT = [5, 3];  // DS18B20 1-Wire cable
       ```

    4. Derived dimensions block:
       ```
       INNER_W = PI5_W + PCB_TOL;
       INNER_D = PI5_D + PCB_TOL;
       INNER_H = STACK_H + 5;  // 5mm clearance above stack top
       OUTER_W = INNER_W + 2 * OUTER_WALL;
       OUTER_D = INNER_D + 2 * OUTER_WALL;
       TOTAL_W = OUTER_W + 2 * FLANGE_W;
       ```

    5. Render entry point:
       ```
       pi_case_tray();
       translate([0, OUTER_D + FLANGE_W + 10, 0]) pi_case_lid();
       ```

    6. Module `pi_case_tray()` — difference of union (solid) minus cutouts:
       - `pi_case_base_plate()` — floor + flanges (same pattern as sensor-cluster)
       - `pi_case_outer_walls()` — hollow box walls
       - `pi_case_standoff_bosses()` — 4 bosses at Pi mounting hole positions (M2.5 through-hole for rubber standoffs, per D-03)
       - `pi_case_lid_bosses()` — 4 corner bosses for lid screws
       Minus:
       - `pi_case_standoff_holes()` — M2.5 clearance through bosses AND floor (through-hole for rubber standoff bolt)
       - `pi_case_fan_cutout()` — 40mm fan aperture + 4x M3 mount holes on one side wall (per D-04). Position fan centre at cooler height above floor
       - `pi_case_exhaust_vents()` — ventilation slots on the OPPOSITE wall from the fan (4-6 horizontal slots, same height range as fan). Per Research pitfall 2: intake on one side, exhaust on the opposite side
       - `pi_case_gx12_cutout()` — 12.5mm circular cutout on a side wall (per D-05). Position on rear wall (opposite HDMI/USB side)
       - `pi_case_sma_cutout()` — 6.7mm circular cutout on a side wall (per D-06). Position on same wall as GX12 or adjacent, near GPS module location
       - `pi_case_cable_slots()` — individual rectangular slots per cable type on the HDMI/USB side wall (per D-07). Each slot positioned at the correct height for its port. Slots start FLOOR + 2mm above floor (per sensor-cluster convention). Add a 3mm zip-tie channel (small tab inside wall) below each slot for strain relief
       - `pi_case_flange_holes()` — 4x M4 bolt holes with counterbore in flanges (same pattern as sensor-cluster)
       - `pi_case_lid_boss_holes()` — pilot holes in lid bosses

    7. Module `pi_case_lid()` — flat plate + inner lip + screw clearance holes (same pattern as sensor-cluster lid). Lid has ventilation slots above the fan/cooler area (the cooler needs to exhaust upward if the fan is on the side wall).

    **Critical design rules:**
    - All boolean subtractions use `+ 0.2` depth and `-0.1` entry face (per sensor-cluster convention)
    - Fan intake on one wall, exhaust vents on opposite wall, cooler fins aligned inline with airflow path (per Research pitfall 2)
    - Cable slots use right-angle adapter dimensions (HDMI adapters ordered per Brain vault), not straight cable dimensions (per Research pitfall 3)
    - No USB storage ports accessible from outside without opening the lid (per Research security domain)
    - Every parametric constant has an inline comment with source ("measured YYYY-MM-DD" or "verified RPi mechanical drawing" or "per D-XX")
    - Modules named descriptively: geometry not intent (e.g. `fan_cutout` not `cooling_system`)

    **What to avoid and why:**
    - Do NOT use self-tapping post holes for Pi mounting — D-03 specifies rubber standoffs (through-hole + nut, not self-tap)
    - Do NOT seal the top above the cooler — the active cooler needs exhaust space. Lid ventilation slots required
    - Do NOT model a straight HDMI cable exit — right-angle adapters are in use (Research pitfall 3)
    - Do NOT hardcode any dimension that can be derived from a constant — all geometry must be parametric (Research pitfall 1)
