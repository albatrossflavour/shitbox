```python
def _check_throttled(self) -> None:
    """Read and decode throttle bitmask; feed the alerts helper every cycle.

    PWR-01 fix: the alert trigger is `raw & 0xf` only (current-undervoltage,
    current-frequency-capping, current-throttling, current-soft-temp). Sticky
    since-boot bits 16-19 are decoded for logging but never drive the alert.
    """
    raw = self._read_throttled()
    if raw is None:
        return

    low = raw & 0xf
    active = bool(low)

    # Logging path: state CHANGE (low nibble) — not the state itself.
    with self._lock:
        prev = self._last_throttled_raw
        self._last_throttled_raw = raw
    if prev is None or (prev & 0xf) != low:
        decoded = _decode_throttled(raw)
        log.warning(
            "throttle_state_changed",
            raw_hex=hex(raw),
            current=decoded["current"],
            since_boot=decoded["since_boot"],
        )

    # Side-effect bundle for the undervoltage transition (per D-04):
    # TTS + buzzer fire together, gated once by the helper's sustain counter.
    def _undervoltage_side_effects() -> None:
        beep_under_voltage()
        speak_under_voltage()

    # Alert path — called every cycle. Helper owns sustain + once-on-transition.
    alerts.fire_alert(
        "UNDERVOLTAGE",
        active,
        "UNDERVOLTAGE DETECTED",
        _undervoltage_side_effects,
        sustain_required=2,
    )
    # Recovery path — also called every cycle. Helper owns once-on-transition.
    # Note per D-06 the recovery subtype is the suffixed form (_CLEARED) — the
    # frontend branches on the suffix to render the green overlay (UI-SPEC line 156).
    # Because the helper tracks subtypes as opaque keys, we bridge the pair by
    # arming recovery under the same subtype we fired under, then using the
    # _CLEARED subtype only in the emitted event. We accomplish that by calling
    # fire_alert on "UNDERVOLTAGE" and fire_recovery on "UNDERVOLTAGE" too, but
    # with a post-emit rewrite of the event subtype. Simplest clean approach:
    # pass the active-false signal to fire_recovery under the "UNDERVOLTAGE"
    # subtype key (so the helper's fired flag matches) and let the message +
    # the helper internals handle it — then we push the _CLEARED subtype event
    # directly from here when fire_recovery has just flipped fired → False.
    #
    # The helper's fire_recovery(subtype="UNDERVOLTAGE", ...) emits an ALERT
    # event with subtype="UNDERVOLTAGE" — but for the frontend green branch we
    # need subtype="UNDERVOLTAGE_CLEARED". So we either:
    #   (a) Emit the clear event inline here (bypassing the helper's push) and
    #       use the helper only for sustain bookkeeping, OR
    #   (b) Pass "UNDERVOLTAGE_CLEARED" as the subtype to fire_recovery and
    #       accept that fire_recovery keys off a DIFFERENT subtype than fire_alert.
    #
    # Option (a) is cleaner because the helper's fired flag lives on the
    # "UNDERVOLTAGE" key and the _CLEARED subtype is a display-only concern.
    # We implement (a): call fire_recovery with "UNDERVOLTAGE" internally, and
    # wrap the recovery tts_fn to also push the _CLEARED event with the proper
    # subtype string.
    def _power_restored_side_effects() -> None:
        speak_power_restored()
        # Emit the recovery event with the suffixed subtype the frontend expects.
        import time as _t
        from shitbox.health.alerts import dashboard_push_event as _push
        _push(
            {
                "type": "ALERT",
                "subtype": "UNDERVOLTAGE_CLEARED",
                "message": "POWER RESTORED",
                "ts": _t.time(),
            }
        )

    alerts.fire_recovery(
        "UNDERVOLTAGE",
        active,
        "UNDERVOLTAGE RECOVERY",  # unused — the tts_fn emits the real event
        _power_restored_side_effects,
        sustain_required=2,
    )
```

Design note on the recovery subtype bridge (important for the executor): the helper's `fire_recovery` tracks the `fired=True` flag against whatever subtype key the caller passes. We use `"UNDERVOLTAGE"` as the key because that's where `fire_alert` marked `fired=True`. The helper then emits a push event with `subtype="UNDERVOLTAGE"` — which the frontend would render as RED (failure). To get the GREEN branch, we need the emitted event's subtype to end in `_CLEARED`. The cleanest fix is to have the recovery `tts_fn` emit the correctly-suffixed event itself (via `alerts.dashboard_push_event`) AND perform the TTS in the same callable. The helper's own emission for the recovery edge is effectively overridden because the frontend routes the TWO events (helper-emitted `"UNDERVOLTAGE"` + our side-effect `"UNDERVOLTAGE_CLEARED"`) — but the helper-emitted one would show a RED overlay briefly.

To avoid that double-emission, refine: the helper emits the push event UNCONDITIONALLY on the recovery edge. So we either (i) accept a brief red flash then a longer green overlay (bad UX), or (ii) change the approach: call fire_recovery with subtype="UNDERVOLTAGE_CLEARED" and accept that the helper has NO `fired=True` on that key → fire_recovery is a no-op per the helper's own `if not prev.fired: return` guard.
