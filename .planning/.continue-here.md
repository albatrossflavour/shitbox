<decisions_made>

- Cabin uses `setpts=PTS-STARTPTS+{intro_duration}/TB`, not `setpts=PTS+{intro_duration}/TB`. The `-STARTPTS` is load-bearing: after `-segment_wrap` cycling, cabin segments have non-zero start PTS, and preserving that offset rendered the PiP invisible on the first Pi deploy.
- Timelapse frame grab uses `-skip_frame nokey` because H264 passthrough segment boundaries are not keyframe-aligned (camera controls GOP). Decoding from packet 0 produced mid-GOP garbage → black frames.

## Critical Anti-Patterns (do NOT repeat these)

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Preserving source PTS origin when shifting overlay input | Using `setpts=PTS+offset/TB` on a segment muxer source means the overlay inherits the cycling segment's non-zero start PTS and disappears. | advisory | Always `setpts=PTS-STARTPTS+offset/TB` on ring-buffered inputs before using the stream in an overlay chain. |
| Decoding arbitrary frames from H264 passthrough segments | Passthrough segments are byte-accurate TS cuts, not keyframe-aligned. `ffmpeg -i segment.ts -frames:v 1` returns mid-GOP mush. | advisory | Use `-skip_frame nokey` as an input option when extracting single frames from H264 ring-buffer segments. |
