<blockers>

- **IMU sampler is for the wrong chip.** `src/shitbox/events/sampler.py` is hardcoded to MPU6050 (`0x68`, big-endian block read starting at `ACCEL_XOUT_H = 0x3B`, `PWR_MGMT_1` wake sequence). Real hardware on this Pi 5 is LSM6DSOX (`0x6A`, little-endian, different register map, `CTRL1_XL`/`CTRL2_G` wake). Nothing at `0x68` on the bus. Phase 11 rewrites this.
- **Daemon recovery path broken.** When the daemon detects a stuck i2c bus, it tries to `sudo reboot` as a last resort. The systemd unit has `NoNewPrivileges=true`, so sudo refuses. Recovery is effectively a no-op. Fix candidates (deferred to Phase 11): DT-level bus recovery overlay (`scl-gpios`/`sda-gpios`) so the kernel does the bit-bang dance itself, or systemd watchdog fallback instead of shelling to sudo.
- **MBTiles file missing on Pi.** Tile handler logs `unable to open database file` for every request because `dashboard.tiles_path` points at a file that isn't there. Not a bug; just needs `tools/download_tiles` run against the rally corridor and the output rsynced to the Pi. Separate from Phase 11; can be done any time.
- **PM2.5 sensor (DFRobot SEN0460) not on the bus.** Expected at `0x19` per v2 hardware plan but not responding. Hardware not yet chained. Phase 11 will land a collector skeleton that's enabled when the sensor arrives.
</blockers>
